Root cause (src/lib/forms/payroll-deduct.ts, statedPayrollDeduct): an amount
beside "payroll deduct" ("payroll deduct $25", "$25 payroll deduction") is read
as a deduction to take, and only a fixed list of negative phrasings could stop
it. The first F-01 fix added the reported phrasings, but "we're not doing the
$25 payroll deduction", "skip the $25 payroll deduction", "no need for the $25
payroll deduction" and "payroll deduct $25 does not apply" still came back Yes;
"we did not waive the $25 payroll deduction" came back No.

- A Yes read from an amount or a verb (not from "yes" / "applies" /
  "applicable") is a Yes only when no word beside it, up to a comma either
  side, denies, waives, cancels or replaces it. Otherwise the clause is
  unclear: nothing is read and the manager is asked.
- "payroll deduct $25 does not apply" / "$25 payroll deduction is not needed"
  is a No.
- A denied waiver ("we did not waive …") is unclear, never a No.
- In a conversation, a later unclear statement about the deduction withdraws
  an earlier Yes, so the card asks again.
- A comment named the sibling app; it now says Ask Bubbles.

Regression impact: no reading becomes Yes that was not Yes before; some
amount-only sentences with a denial next to them now ask instead of answering.

Tests: qa-f01b-payroll-fail-safe.test.ts (31). 16 fail on main 3395e8d and 10
on the first F-01 fix; all 44 payroll test files (2,533 tests) pass.
