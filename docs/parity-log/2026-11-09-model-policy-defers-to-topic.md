# Sibling app only: a short cash drawer is not the slot model's "Handling Theft" (MODEL_POLICY_DEFERS_TO_TOPIC_ENABLED)

The sibling app's round-7c live test, 3a (9 Nov 2026): after "create a corrective action for <P>, he was late opening the salon on 11/2", the request "I need another corrective action for <P>, his cash drawer was short $20 on 11/3" read as theft. Neither turn names theft. There, the slot model read the policy heading "Handling Theft", and the sibling's `stateForTurn` keeps a heading the models read in the new request itself. That heading was written in front of the turn ("Policy reference: Handling Theft …"), and the topic table read "theft" from it. The fix there: where the manager's own words name an incident the code reads, a model heading outside that incident's sections is not taken.

Not needed in this app: its slot merge (`ai/intent-slots.ts`) never puts the model's policy heading into the saved form state, and its `stateForTurn` clears the earlier policy on a new request without keeping one the models read. Checked on main 48a3353f through the replay pack, with the slot model scripted to read "Handling Theft" for that turn. The card reads "**Policy:** this reads as **Standards of Conduct** — cash handling" either way, and never theft.
