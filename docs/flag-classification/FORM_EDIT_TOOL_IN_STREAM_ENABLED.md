## Before this table: what the first flag-on run found, and what was done

The first run on the rebased code (same command) changed 8 tests. None was a
code regression; each was a test reading the old path:

- `form-edit-single-writer-flags-off.test.ts` (c) control: its "no model call
  added by the single writer" count read the shell's tool flag, and the tool
  makes the answering call ahead of the old chain. The tool flag is now
  pinned off in that file, like the Step B flags (INTENDED-HARNESS, fixed in
  the harness).
- Six replay-pack Step B cases and `nov4-live-ca-t6-step-b-add`: they script
  Step B's patch model, which this flag skips by design. The replay harness
  now sends the same scripted reading as an `edit_form` call when the tool is
  offered (add → append, replace → set, clear → clear), so they run on the
  tool path with the model's same choices (INTENDED-HARNESS, fixed in the
  harness). They hold; the six OPEN-in-production ones now hold with the tool
  on (the rows above).
- `nov3-stepb-invented-sentence-refused`: see its replay row; its flag-on
  expectation is commented in `nov3-step-b-cases.ts`.

Eval (`npm run eval`, `evals/flags.json` on = the single writer and this
flag, stubbed models): no case changed; latency p50/p95 off 70/249 ms, on
67/242 ms; total off 2125 ms, on 2085 ms.
